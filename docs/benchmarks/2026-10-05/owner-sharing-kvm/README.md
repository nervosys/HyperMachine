# Real KVM owner-managed browser sharing

Ten functional cases pass with a real local nested-KVM guest and one fork, owner-scoped API credentials, the current isolated release control plane and CLI, verified API/proxy TLS, and node mTLS plus cluster token. The accepted default-MMIO daemon/kernel/buffered guest are immutable and hash-checked before and after. No public DNS, managed competitor endpoint or performance measurement is involved.

The owner CLI replaces grants twice with the same request and reads them back. Browser requests reach the actual guest with exactly the provisioned identity, without Basic credentials or the forged identity. Wrong-owner/legacy keys refuse grant writes; missing/incorrect login and absent grants deny. The custom domain uses the current sandbox grant, and a fork does not inherit it. Two actual shipped control-plane process restarts preserve active grants and revocation. Revocation returns 401 without resuming the paused real guest, and old grant replay returns 409. A current regrant allows auto-resume; operator delegation reload and expired stored grants enforce denial.

The current control binary is SHA256 `633fff09e0c5f2703e1405d5a95f3764af351d1bbf9cdd784854dfccff59197b`; CLI is `c4b82db62ec7bc4e717ddff54d6edb1ed697d9738807bd2f3b29660d0d3d3c2f`. The release build used `--locked` in the authorized isolated tree with accepted protected hashes checked before/after. Eleven selected source/dependency inputs match the workspace, not a full source closure. Provisional root core implementations were not read, built or staged.

The initial fixture failed before guest creation because the generated CA lacked a key-usage extension required by Python's strict TLS verifier. Its driver, report and service logs are retained. The corrected CA adds explicit critical CA/key-signing usage; certificate verification remains enabled. The final run deletes parent and fork, confirms empty inventory, waits for all five registered processes to stop, removes its private directory and leaves inputs unchanged. An independent check confirms case/inventory/directory results and stopped-process evidence. Certificates, private keys and generated credentials are not archived. Redis remains running across the two control-plane restarts; its own five-hard-restart gate is separately documented.

This closes this local owner API/CLI → TLS proxy → mTLS node → real guest sharing/restart fixture. Redis outage during live KVM traffic, hardware power loss, managed failover, arbitrary nodes/kernels, tenant/team isolation, SSO, verified email, long-lived stream revocation and performance superiority remain unverified or absent. Existing admitted streams retain original admission.

Reproduce with `tools/verify-owner-sharing-kvm.py --daemon <accepted-node> --control <current-control> --cli <current-cli> --kernel <accepted-kernel> --initrd <accepted-guest> --output <new-owned-output-directory>`. Verify the archive with `python verify.py`.
