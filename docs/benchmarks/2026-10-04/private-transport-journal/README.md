# Benchmark failure evidence preservation

The checker now appends and flushes each completed benchmark row to `private-transport-rows.jsonl` before socket close, and writes `private-transport-benchmark.json` before asserting that all scored requests succeeded. A later scored failure therefore retains successful and failed operations rather than losing the cohort when the final report is not reached. Failure rows retain only a categorical exception type; successful timing summaries remain conditional on success and always accompanied by planned/success/failure counts.

The normal owned KVM run passes **30 checks and 128/128 scored requests** plus eight warmups, with every guest and process cleaned up. Its journal and standalone benchmark exactly match the final report. Production daemon/source is unchanged from the concurrent-lookup candidate; only the checker changed.

A separate frozen checker copy injects one `TimeoutError` after upgrade of the first scored private 64-byte operation. All **136 rows** are retained, with **127/128 scored successes and one explicit failure**. The checker raises its expected cohort-failure error and emits no success report. The wrapper tracks actual child process handles and verifies all **23 children are terminal** afterward. The injected copy differs by exactly one condition; no fault switch was added to the production checker. Failed-cohort timing rows are diagnostic evidence, excluded from performance rankings.

Run `python3 verify-results.py` to recompute journal counts, compare normal report/snapshot rows, and verify the exact isolated injection. Drivers preserve original absolute owned-input paths; reproduce with equivalent frozen inputs and fresh output paths. This verifies graceful sample-error evidence preservation, not host-crash durability: flushing Python buffers is not an fsync guarantee, and interrupted work cannot report uncompleted operations. Failure-path process cleanup does not prove the successful guest-delete accounting of a completed report. All 138 permitted root/isolate source pairs, accepted isolated core hashes and normal runtime inputs were revalidated; protected root core files were neither read nor built. No new competitor or performance win is claimed.
