# Private address ledger

The source-incarnation-bound ledger allocates synthetic addresses from `198.18.0.0/15`. Its classifier reserves the entire pool, including unknown addresses, so private requests cannot fall through to Internet routing. Each of at most 4096 entries binds source/destination membership generations and network tag. Allocation is atomic under one mutex; repeated identical route allocation returns one address. Entries are append-only and retained after revocation. Actual TCP ports are checked during fresh paired-snapshot authorization.

Three tests cover 32 concurrent allocators, stable snapshot/restoration, stale generations after rejoin, pending/expired source refusal, owner/incarnation mismatch on restore, unknown pool addresses, invalid/duplicate bindings, bounded input and capacity exhaustion preserving existing bindings. Final full cluster suite: **109 passed, zero failed, one ignored**, with owned Redis enabled for both store contracts. Redis exited zero and was reaped. ACL opt-in fault tests remain unset. Address tests themselves are in-process; this run does not persist addresses in Redis.

Targeted v1 passed with a 1 MiB snapshot input limit. Final source increases that bound to 4 MiB to accommodate all 4096 entries with maximum-length validated identities; full-suite v2 verifies final sources. Catalog checks verify 137 permitted root/isolate source pairs and accepted isolated core hashes. Protected root core sources were neither read nor built.

The caller must atomically persist the complete ledger before exposing an address, preserve it through lifecycle operations, and refuse restoration of an older snapshot. External rollback/crash durability is not implemented or proved here. A production router must use a fresh paired snapshot and pin the resulting claim through connector setup; checking an address then dialing only its destination/tag would discard the generation binding. Store persistence, pinned connector integration, guest DNS namespace, daemon wiring and KVM guest-to-guest tests remain unfinished. No performance advantage follows from these functional checks.
