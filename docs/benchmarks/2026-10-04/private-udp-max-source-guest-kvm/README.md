# Maximum-size actual source guest private IPv4 UDP

The production fragmentation path passes **37 checks** in an owned real-KVM fixture. An Internet-disabled source guest resolves the private target, then sends empty-first, 13-byte binary, 1,280-byte and **65,507-byte** datagrams through its Ethernet gateway, committed private router, generation-bound Rust mTLS connector and receiving target KVM UDP server. Every connected UDP reply matches its exact length and bytes. Source and target are on distinct daemon nodes sharing one WSL host. The source client explicitly permits IPv4 fragmentation; the preceding Ethernet tests independently verify multiple valid-MTU fragments in both directions.

Another owner guest cannot use the numeric private binding. Target membership rejoin invalidates the previous address; UDP refuses, fresh DNS supplies a different address and all four exact payload sizes recover. The same fixture verifies receiving UDP framing/authentication, real guest TCP/DNS, source/target TCP membership stream closure, source pause/resume and cleanup. All processes are reaped and zero guests remain. The tiny receiving UDP closure time is observed after waiting for TCP closure and is not UDP revocation latency.

The daemon uses the accepted isolated production sources from the preceding fragmentation tests. All 139 permitted root/isolate source pairs and accepted isolated core hashes were verified before building and after running. Protected root core sources were not read or built. This turn extends only the owned C client and checker expectations; it does not change production code. The derived fixture image preserves the accepted base/production guest agent and independently rebuilds byte-identically.
