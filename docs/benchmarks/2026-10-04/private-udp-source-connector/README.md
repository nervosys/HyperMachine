# Generation-bound private UDP source connector

`PrivateNodeConnector::open_bound_udp` now opens the private IPv4 UDP receiving endpoint with exact `hv2-udp/1` negotiation. TCP and UDP share fixed source identity, source lease validation, fresh paired membership/owner/lifecycle checks, live node and HTTPS origin validation, expected generation/port/tag binding, post-upgrade route revalidation and the total 15-second setup deadline. Stale bindings refuse before node HTTP contact. The returned stream retains the local source activity lease through reads, writes, half operations and cleanup; callers must encode/decode bounded datagram frames.

The final **119-test cluster suite passes** with owned ephemeral Redis; one opt-in test is ignored. Three new real owned-mTLS fixture groups verify UDP endpoint/protocol/context selection, exact early framed and binary bytes, TCP upgrade refusal, bad token/anonymous TLS refusal, and source/destination generation, destination placement and local lease changes during setup. The shared stale-address proof now exercises both TCP and UDP for old destination generation, wrong source generation/identity, invalid port and wrong network, verifies every lease drops exactly once, and observes no connection at the owned destination listener. Existing TCP, transient contention and setup deadline tests remain passing.

Memory and Redis route, address-ledger and source-router contracts each complete twice, and Redis is reaped with exit zero. Redis saves/AOF are disabled; this is not crash durability proof. TLS peers are owned echo fixtures and local source leases are mocked. This does not yet prove the new Rust UDP source connector against the real receiving KVM endpoint, nor source guest Ethernet UDP interception, private router UDP dispatch or complete guest-origin delivery. Those integration steps remain unfinished. No new competitor or performance claim is made.

Run `python3 verify-results.py` to verify test groups, contract markers and cleanup. `driver.py` preserves the full owned Redis/cargo invocation with the accepted isolated tree and separate Cargo target. All 138 permitted root/isolate source pairs and accepted isolated core hashes were rechecked. Protected root core files were neither read nor built. The only changed production file is `private_node.rs`, preserved here; earlier receiving daemon binary evidence remains separate.
