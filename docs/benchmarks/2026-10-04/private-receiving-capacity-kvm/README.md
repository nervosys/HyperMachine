# Real private receiving capacity and recovery

An owned mTLS host client holds **125 additional private UDP tunnels** to a real KVM target alongside existing fixture routes. Each new tunnel carries an exact unique binary payload; all held tunnels are checked again at saturation. The next request returns **503** under the configured 128-slot shared private receiving budget. Existing private UDP traffic and a fresh standard UDP tunnel continue to echo exact payloads. Closing one held tunnel allows replacement on the first attempt (about 9.9 ms measured including opening and exact echo); refilling it restores 503 for excess requests. Finally blocks close all held sockets, and existing traffic still works afterward.

**53 KVM checks, 128/128 scored benchmark operations and full guest/process cleanup pass.** The benchmark is an additional regression cohort, not a new ABBA performance comparison. Production daemon source/binary is unchanged from the accepted setup-overlap release. The new checker flag is `--private-receiving-capacity`, requiring private receiving UDP. The shared receiving budget covers all private routes, not 128 extra UDP tunnels per VM. This fixture does not independently inventory the three preexisting slots; report the observed 125 additional tunnels rather than infer their exact composition.

The retained checker implements the exact traffic/status assertions and cleanup; report records their results. Raw benchmark rows, daemon log, stdout, source context and driver are frozen. Run `python3 verify-results.py` to verify report/rows, independently recompute all timing statistics, and check binary/source identities and cleanup. Drivers retain owned original paths and require fresh outputs. The prior release build/64 daemon tests and full ABBA evidence are in `../private-setup-overlap-release-abba/`. Protected root core files were not read or built.

This is serialized admission with many simultaneously held real tunnels, not concurrent setup saturation, simultaneous worker throughput, injected mid-setup cancellation, independent-host capacity, resource profiling or competitor measurements. TCP/mixed-protocol saturation and broader races remain unverified.
