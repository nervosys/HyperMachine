# Combined private authorization snapshot

The receiving private TCP/UDP authorization path now calls `private_route_snapshot_with_live_nodes`. Redis returns both endpoint records, memberships and requested live-node records in one atomic script. It continues to use `GET` inside Lua, preserving GET lookup refusal behavior, and decodes node records as typed `NodeInfo` so malformed state fails closed. Other stores use a default fallback that retains the existing concurrent route/node lookups without caching.

Both receiving setup barriers and ongoing revocation checks remain fresh. Placement, trusted owner, membership/generation, local actual-VM/pending/incarnation/expiry, lifecycle, mTLS/token, capacity and activity checks remain in place. The Redis setup path now issues two authorization commands for two barriers instead of six; each barrier still reads the same six records. The atomic node/route view additionally avoids independent read timing within each Redis barrier.

**120 cluster tests** pass with owned ephemeral Redis, including Memory and Redis live-node contracts for missing source/destination nodes, removal, expiry and recovery. Existing route/address/router contracts also run against both stores without skips. **64 ordinary daemon tests** pass; two KVM-only tests remain ignored in that suite. The owned Redis process is reaped. The initial test attempt is retained/excluded: it assumed sub-second Redis node TTL precision and left fixture nodes behind for a later count assertion. The corrected contract uses a one-second TTL, waits beyond expiry and cleans up its nodes/records.

All 139 permitted root/isolate source pairs and accepted isolated core hashes are revalidated, updating only authorized `store.rs` and `forwards.rs`. Protected root core files were not read or built. Run `python3 verify-results.py` for suite results, named contracts, source snapshots and cleanup. Frozen drivers preserve locked isolated Cargo invocations; fresh output paths are required. The manifest pins every payload.

This is an implemented setup-work reduction, not a measured performance win. Candidate release/KVM lifecycle and paired latency verification remain outstanding. The preceding release UDP comparison is the pinned unchanged baseline (`0250dab6fd392c871aa65e041be5b604c690da43a4c296a81e267471b2d9ccc9`), not evidence for this changed candidate. Do not reuse its timings as candidate results. IPv6, other race/stress cases, independent hosts and external competitor performance remain unfinished or unmeasured.
