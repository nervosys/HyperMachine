# Bounded private UDP gateway session foundation

The gateway's `PrivateNetwork` hook now supports `dial_udp`, refusing unsupported hooks by default without opening an ordinary UDP socket. The production daemon adapter delegates to its fixed-source private router. A new gateway session relay preserves bounded big-endian u16 framed datagrams over an already authorized stream. It accepts empty datagrams, refuses lengths above 65,507 before allocating a receive payload, and refuses oversized outgoing payloads before writing a prefix. Framing does not sniff payloads, inject headers or invoke an Internet/SOCKS dialer.

Session waits include queue backpressure and are bounded by inactivity and absolute lifetime; either completed read or write resets inactivity, while partial frames do not. Closing the consumer or input queue terminates the session. Cancelling the relay future drops both stream halves, releasing upstream transport ownership. Callers must supply bounded packet queues; the session module defines a two-packet queue depth for the forthcoming stack integration. It does not yet enforce global session admission because Ethernet interception is not implemented.

All **197 networking tests** and **64 ordinary daemon tests** pass; two explicit KVM-only daemon tests remain excluded from that suite. Four new duplex proof groups verify exact empty/binary/maximum datagrams and boundaries, oversized/truncated frame refusal, idle/absolute lifetime expiration, a full two-packet output queue, consumer closure and cancellation. Peers observe transport closure. These use owned duplex streams, not actual source guest Ethernet or real mTLS/KVM traffic.

The actual gateway currently still drops non-DNS UDP packets. Ethernet destination socket allocation, per-peer session admission/queue management, stack reply emission and gateway teardown wiring remain unfinished, followed by real guest-origin KVM UDP verification. The new framing/helper and daemon hook are foundations for that path, not complete guest UDP networking or product parity. No competitor or performance claim is added.

Run `python3 verify-results.py` to verify test totals and session groups. `driver.py` retains the isolated-tree cargo invocations. All **139** permitted root/isolate source pairs and accepted isolated core hashes were verified; protected root core files were neither read nor built. Source snapshots here preserve the gateway module/hook, bounded relay and daemon adapter changes. No new runtime daemon binary evidence is claimed.
