# Private IPv4 UDP Ethernet gateway

The guest gateway now creates UDP sockets only for destinations claimed by the fixed-source private network hook. It dispatches per-peer framed sessions through `dial_udp` and emits replies with the original private destination address/port. Ordinary non-DNS UDP remains dropped. Private refusal never opens an ordinary host UDP socket or uses Internet policy, SOCKS, payload sniffing or header injection.

TCP and UDP sessions share `max_connections` admission. Destination sockets are also bounded by that cap. Per-peer incoming/outgoing queues and per-destination socket packet metadata are bounded to two packets; UDP pressure drops whole packets, not fragments of a framed stream. One pending reply is retained when the socket queue is full. Connecting sessions use the existing connect timeout, then the framing relay enforces 30-second inactivity and 600-second absolute lifetime. Finished sessions release their transport task/queues; unused destination sockets are reclaimed after a short drain interval. Dropping the stack aborts every remaining private UDP task.

All **200 networking tests** and **64 ordinary daemon tests** pass; two explicit KVM-only daemon tests remain excluded from that suite. Three new actual Ethernet/smoltcp guest groups verify private DNS plus exact empty-first, HTTP-looking binary and 1,280-byte datagrams with Internet disabled and an unusable SOCKS proxy; private refusal under permissive Internet policy; a one-connection shared UDP/TCP cap; and transport closure after gateway drop. Session framing/timeout/backpressure tests from the preceding archive remain passing.

The initial fixture used a 600-ms reply gate after DNS and failed before reaching the private UDP hook; a binary-first diagnostic also failed at that gate. Allowing three seconds retained empty-first coverage and passed all cases. The original failed suite is preserved as `excluded-short-deadline-tests.txt`, excluded from final proof. Neighbor-resolution scheduling is consistent with the observation but was not independently isolated as the cause. An earlier test audit-field compile error is retained separately. Temporary diagnostic prints are removed from final source. No product latency claim follows from this fixture deadline correction.

The UDP transport hook here uses owned duplex echo peers, not the real cluster connector/receiving KVM endpoint. Actual source guest KVM UDP delivery, private lifecycle revocation through Ethernet, UDP-specific pending/owner/race/saturation schedules, independent hosts and crash durability remain unverified. The stack currently lacks IPv4 fragmentation support: this proves datagrams that fit the guest MTU, not maximum 65,507-byte Ethernet delivery. Maximum framing was verified separately; private IPv6 and fragmentation remain unfinished. No competitor or performance win is claimed.

Run `python3 verify-results.py` to verify final test groups and totals. `driver.py` preserves the isolated-tree cargo invocations. All 139 permitted root/isolate source pairs and accepted isolated core hashes were revalidated; protected root core files were neither read nor built. Source snapshots preserve packet/socket/session implementation and guest fixture. No new runtime daemon binary is claimed here.
