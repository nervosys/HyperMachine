# Actual source guest stream membership revocation

The final **31-check** owned KVM fixture establishes a long-lived TCP stream from an Internet-disabled source guest through its Ethernet gateway, Rust private router/mTLS connector and receiving target guest on a distinct daemon node. It observes the exact new `source-probe` echo before removing the source guest's private membership. The client exits or becomes a zombie (socket resources closed) within **949.14 ms** of the removal response. Its writer holds stdin open for 30 seconds and the client inactivity timeout is 15 seconds, outside the five-second closure gate.

While the source membership is absent, numeric reconnect is refused. Rejoining the source to the same tag yields a different private DNS binding; the old numeric address still refuses, and fresh-name traffic restores the exact 19-byte binary echo. The same run repeats target-membership guest stream revocation, one-MiB traffic, owner/tag DNS isolation, stale target binding and actual source pause/resume. Zero guests remain and every daemon/control/Redis/CLI/gateway process is reaped.

Both daemon nodes share one owned WSL host. This is functional end-to-end evidence, not a latency percentile, revocation SLA, independent-host proof or competitor win. The fixture does not attribute closure to a specific enforcement layer. Local source VM identity/pending changes during active traffic, owner changes, both half-close directions, saturation, private UDP and crash recovery remain unverified or incomplete.

The earlier successful run reused the target probe marker, allowing ambiguity in readiness of the second client. Its report is retained as `excluded-reused-marker-report.json` and excluded from the strengthened new-stream proof. The final checker uses a distinct source marker, so stale target output cannot satisfy source readiness.

Run `python3 verify-results.py` to verify final result flags, distinct-node scope, closure bound and cleanup evidence. `driver.py` preserves the original absolute owned-fixture input paths; reproduction elsewhere requires equivalent frozen inputs and a fresh output path. Production source/binary is unchanged from the previously tested concurrent authorization candidate. All 138 permitted root/isolate source pairs, accepted isolated core and runtime hashes were rechecked. Protected root core files were neither read nor built.
