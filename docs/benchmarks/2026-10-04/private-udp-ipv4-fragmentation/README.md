# Bounded private IPv4 UDP fragmentation

The gateway now enables IPv4 fragmentation/reassembly with a 65,536-byte transmit buffer, two 65,536-byte receive reassembly buffers and a 32-segment assembler limit. Incomplete receive sets expire after five seconds. First fragments can create only bounded private destination sockets; complete datagrams still require interface reassembly/checksum validation before source session admission and authorization. Other UDP remains dropped.

The prior one-second unused destination socket drain window could expire before a valid delayed fragment set completed within the five-second reassembly limit. The socket window is now five seconds as well. A new guest Ethernet test delays the rest of the first full-size datagram by 1.1 seconds and verifies the destination remains available for reassembly and exact reply delivery.

All **201 networking tests** and **64 ordinary daemon tests** pass; two explicit KVM-only daemon tests remain excluded from that suite. The private UDP Ethernet test now preserves the maximum **65,507-byte payload**, in addition to empty/binary/1,280-byte packets. Guest counters assert multiple UDP IP fragments crossed the actual Ethernet link in both directions, and every frame respects the 1,514-byte device limit. Refusal, shared TCP/UDP admission, session framing/timeouts and gateway teardown tests remain passing.

These use a smoltcp guest and owned duplex transport hook, not actual maximum-size source KVM UDP. The earlier actual KVM proof covers only datagrams within the MTU and uses its archived binary. Full-size KVM routing, reordering/receive-buffer exhaustion/expiry runtime schedules, active guest UDP revocation, private IPv6, independent hosts and crash recovery remain unverified or incomplete. The configured buffers/assembler add memory capacity; no memory/CPU/performance win or competitor superiority is claimed.

Run `python3 verify-results.py` to verify final test groups/totals. `driver.py` preserves isolated-tree cargo invocations. All 139 permitted root/isolate source pairs and accepted isolated core hashes were revalidated; protected root core files were neither read nor built. Cargo tests use `--locked`; no dependency version change is required. Source snapshots preserve feature configuration, packet socket lifetime and fragment-count/delay fixtures. No new runtime daemon binary is claimed here.
