# Concurrent private UDP at receiving saturation

**32 workers complete 3,200/3,200 exact datagrams**, cycling 64, 1,280 and 65,507-byte payloads with unique worker/sequence identities and no retries. Each worker owns one held tunnel. The target holds 125 additional private UDP tunnels alongside existing fixture routes under the shared configured 128-slot receiving budget. Excess and refilled requests return 503; existing private and standard traffic survive; a closed slot recovers on the first attempt. **54 KVM checks, 128/128 regression benchmark operations and full guest/process cleanup pass.**

The measured workload echoes 70,596,704 payload bytes in 3.063 seconds including worker startup: **21.98 MiB/s aggregate echoed payload throughput**. This is one owned host-to-target mTLS/stream-to-guest-loopback UDP cohort, not source-guest Ethernet, an ABBA optimization comparison, sustained service capacity, CPU/memory efficiency or a competitor ranking. Throughput counts payload once per completed round trip and excludes framing/TLS overhead. No uniform latency or resource improvement is claimed.

The first unbuffered cohort completed 26/32 workers; a repeat with guest telemetry completed 18/32. The repeat's 14 timed-out workers match 14 new UDP receive-buffer errors and 14 drops on the unchanged target echo socket. Retained failed telemetry identifies the fixture queue as a loss location; it does not prove every possible loss mode. The passing workload keeps the same concurrency, payloads and round trips and changes the owned echo fixture to an explicit requested 8 MiB receive buffer. Linux reports an actual 16 MiB buffer. Guest UDP receive/send/checksum/memory errors and echo-socket drops have **zero deltas** during the passing workload. This is a benchmark fixture correction, not a production transport speedup.

`tools/udp-guest-echo.c` accepts bounded opt-in `--receive-buffer` only; defaults remain unchanged. The root owned Linux fixture uses `SO_RCVBUFFORCE`, requires effective buffering and logs requested/actual sizes. `--private-receiving-capacity` requests 8 MiB. The derived image replaces only `bin/hm-udp-echo`; all seven other file/symlink entries, including guest agent and private client, match the accepted image. Two deterministic builds are byte-identical. Production release daemon remains the accepted setup-overlap binary. Compile the fixture with `cc -static -O2 -Wall -Wextra -Werror tools/udp-guest-echo.c`, then use the retained image driver and fresh paths.

Run `python3 verify-results.py` for exact report/journal matches, independently recomputed latency/paired statistics, worker byte totals/throughput, zero passing drop deltas, prior failure drops, image equivalence and cleanup. Checker/driver, raw reports/logs/worker outcomes, kernel counters, image catalogs and input hashes are pinned. Failed cohorts did not publish final guest-count reports; a process inventory found no remaining tracked services after the earlier failure, but that is not full guest-count proof. The first failure remains in `../private-capacity-concurrent-failure/`. Serialized admission/recovery remains documented in `../private-receiving-capacity-kvm/`.
