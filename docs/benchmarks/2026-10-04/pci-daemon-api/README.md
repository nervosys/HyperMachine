# PCI sandbox API acceptance

The daemon now supports operator selection `--guest-transport pci`; default behavior remains MMIO. The shared VM builder applies the selection to template creation, API create, fork, pause/resume and restore. PCI boots omit the MMIO-specific fast-boot argument bundle, while preserving configured NIC boot settings. Template identity includes the resulting command line, separating PCI and MMIO caches. PCI snapshot compatibility is validated by the preceding accepted core implementation.

The same frozen debug daemon passes two authenticated owned API profiles: selected PCI and default MMIO. Each profile passes 27 checks: required template readiness, create, exact guest marker commands, two-child fork, parent/sibling write isolation, three disk pause/resume cycles, second-generation fork, deletion of all four sandboxes and empty inventory. These cover the actual `/sandboxes/{id}/fork` endpoint. 66 daemon tests pass (2 ignored), including selection refusal and transport-dependent template configuration checks.

Failures are retained. The first compiler attempt mixed agent/core error types. Initial runtime harness v1 used a direct-exec argument shape against an endpoint whose cmd is a shell line; create and cleanup passed but exact output failed. Harness v2 corrected exec but incorrectly treated fork items as bare descriptors rather than `{sandbox: descriptor}`. It left two children for orderly daemon shutdown to pause. A separate restart of that owned store resumed and deleted both, verifying empty inventory. Harness v3 uses the actual API envelope and passes; default MMIO passes the equivalent gate. No harness failure is represented as a product success.

Driver files reproduce the protocol checks but use exclusive fresh output directories and a frozen binary path; v1 is an archived failed preparation and must not be rerun over its existing binary. Production source hashes and runtime inputs are recorded in source-context.json. This is a nine-file permitted source catalog, not a full build closure; prior unchanged sources are retained in earlier PCI evidence archives. Builds/tests ran in the accepted isolated tree with --locked. Protected root backend/boot files remain excluded.

This verifies owned KVM/API operation for the accepted Linux guest. Network-enabled PCI nodes, mixed-transport scheduling/migration, public endpoints, other kernels/backends and managed fleet guarantees remain unverified. No performance advantage is claimed.
