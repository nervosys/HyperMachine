# Source guest private gateway KVM verification

Production daemon gateways now install the private router for authenticated mTLS cluster guests with a network interface. Each gateway binds to its actual VM handle via weak references, lazily initializes after committed local registration, and reacquires a local lifecycle/activity lease per operation. Guest DNS/headers cannot select the source. Internet policy, SOCKS and secret/header interception remain separate from authorized opaque private traffic.

Two final runs on the same frozen daemon pass **25 checks each**, with zero guests remaining and all daemon/control/Redis processes reaped. An actual Internet-disabled source KVM guest resolves `<target-id>.team.hv2.internal`, sends exact 19-byte binary bytes (including zero and 255), transfers one MiB of zeros verified by SHA-256, and repeats the binary transfer after target rejoin. A different owner's KVM guest cannot resolve the target; ordinary DNS remains refused for the Internet-disabled source. Target rejoin refuses the old numeric address and publishes a different private address before successful recovery. Both reports identify actual source Ethernet gateway, Rust source router/mTLS connector and target KVM payload origin.

The receiving-path phase separately repeats host mTLS authentication, generation, owner/tag, pause/delete and Redis lookup-outage checks with six live-stream closures per run. Those long-lived closure measurements originate at the host, not the source guest; they are functional observations, not an SLA or benchmark.

Source registry contention now returns WouldBlock rather than permanent revocation. Setup retries within existing deadlines; stream polls withhold bytes, use bounded read/write wakers and one-millisecond timers, and close after one second of sustained unvalidated state. New duplex tests verify both halves resume after transient contention, actual revocation cannot revive, and sustained contention closes without reading queued unchecked bytes. Final full suites: **116 cluster tests passed, zero failed, one ignored** with owned Redis; **64 daemon tests passed, zero failed, two KVM tests ignored**. Explicit KVM evidence is supplied by the separate final fixture runs.

Frozen daemon SHA-256: `795880f95b4a0d201c785de101fb81656a88691aa851a8168973d493706502f1`. Reports verify all kernel/image/control/CLI/gateway input hashes. The source catalog verifies 138 permitted root/isolate pairs and accepted isolated core hashes. Protected root core source was neither read nor built.

Earlier v1 passed 22 checks with the first binary and a short guest payload. Excluded v2 on that binary intermittently refused initial guest TCP after successful DNS. Registry contention handling was corrected, but the exact cause of that failed KVM run was not independently traced; do not attribute it solely to contention. Final v3/v4 use the rebuilt binary and expanded checker and both pass. Earlier/excluded artifacts are retained separately.

This proves same-node private TCP/DNS under the recorded owned conditions. Cross-node source traffic, source-guest long-lived revocation/half-close/saturation, configured guest SOCKS, source pending-registration faults, remote destination pending exclusion during DNS, fork/reboot/migration lifecycle, address-store uncertain-response faults, Redis crash durability/backup rollback protection and competitor performance remain unfinished or unverified. Private UDP is not implemented. Full network parity is not established.
