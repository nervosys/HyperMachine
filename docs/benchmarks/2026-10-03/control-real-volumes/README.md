# Control-plane forwarding to real shared-volume daemons

Both tests in volume_routing.rs pass, including the opt-in real-daemon test. The control plane uses its current in-process router with MemoryStore and two real hv2-sandboxd child processes. Each child uses a separate snapshot directory, the same local volume root and the configured cluster credential. No guests/templates are booted (--no-template).

The real-daemon test creates a volume through the authenticated control plane, streams a 1 MiB binary atomic upload into a nested path, verifies exact on-disk bytes, removes each node in turn from eligibility and verifies exact file/token access through the other node, restores membership, kills/reaps/restarts both daemons on their original addresses, and verifies exact content through the same control plane. Wrong bearer writes are refused, duplicate listings merge, API deletion removes the owned volume, the control-plane task is cancelled/awaited, and every child is killed/reaped. The protocol-node test additionally verifies query preservation and credential replacement before forwarding.

The ignored real-daemon test requires HM_VOLUME_TEST_DAEMON, HM_VOLUME_TEST_KERNEL and HM_VOLUME_TEST_INITRD, then runs with cargo test --locked -p hv2-cluster --test volume_routing -- --include-ignored. Exact binary/kernel/initrd hashes were recorded before the final run and verified afterward in inputs.json. Current test/control/volume source bytes match the accepted isolated checkout. The daemon build provenance remains in ../volume-single-parent-sync/build.log. Private runtime tokens and payloads are not archived; test source uses owned synthetic credentials only.

This establishes forwarding to real filesystem-backed volume handlers and controlled eligibility changes on one shared local filesystem. It is not abrupt node failure under an in-flight write, Redis routing, network filesystem, Kubernetes, TLS/mTLS, power-loss or fleet durability evidence. The router runs in the test process rather than the shipped control-plane executable. No throughput or competitor win is claimed.
