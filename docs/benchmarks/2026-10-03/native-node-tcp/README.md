# Authenticated native TCP node connector

The production connector adapter requires operator-provisioned mutual TLS and a bounded nonempty cluster token. Its internally constructed HTTP/1 client refuses redirects and checks node certificates against the configured shared node name. Only HTTPS origins without userinfo, query, fragment or additional path are accepted. The adapter sends the configured cluster token, never an ingress API key or client-selected target. Errors omit credential content. All setup, including store reads, is bounded by 15 seconds.

Before and after an exact hv2-tcp/1 upgrade it checks the complete stored reservation (owner, destination, public port and protocol), unpaused sandbox, live node and unchanged node identity/URL. This is not an atomic lifecycle transaction: later changes still require node/gateway task cancellation. First-claim VM ownership is not established by this adapter.

Owned loopback mutual-TLS fixtures verify HTTP/1 ALPN, configured cluster-token transmission, absence of an API-key header, early binary upgrade bytes and echo. Combined raw ingress/relay/connector testing verifies exact 1 MiB binary transfer and half-close. Refusals cover wrong owner/destination, pause, missing node, HTTP or decorated node URLs, removed reservation, UDP-only protocol, incorrect upgrade protocol, redirect response, wrong certificate name and foreign CA. Additional setup-race fixtures delete/pause the VM, change it to UDP-only or relocate it to a different node with the same URL before answering the upgrade; the connector refuses all four. Fixture tasks abort on drop if a deadline or assertion prevents awaiting them; successful tests await their completion.
