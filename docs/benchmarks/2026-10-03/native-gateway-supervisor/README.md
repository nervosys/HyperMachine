# Owned native gateway supervision

The gateway supervisor now composes exclusive native TCP/UDP bindings, relay task ownership and one shared session budget. It reconciles complete authoritative reservations, retains identical healthy listeners, signals changed/removed listeners together and awaits relay cleanup before rebinding. Failed binds remain unbound for retry. Child listener exit signals its sibling to stop; dropping supervisor entries aborts owned task trees. Explicit shutdown awaits cleanup with a five-second fallback abort. No durable reservation is altered by listener reconciliation.

Refresh validates all reservations before lifecycle filtering, reads sandbox/node inventories and removes listeners for paused/missing guests or unavailable nodes. Store reads use a five-second async deadline; errors/timeouts close owned listeners. A polling runner accepts 20 ms–60 second intervals, retries snapshot/bind failures and closes on shutdown. This is a library runner, not yet wired to an operator executable or management API. Lifecycle changes take effect when reconciliation observes them; this is not an atomic acknowledgement barrier for external API operations.

Owned echo fixtures verify simultaneous TCP/UDP on one port, unchanged-session retention, active-session closure on protocol changes/pause/node loss, failed rebinding with exact socket release, retry, invalid duplicate snapshot refusal, reconstruction using the same MemoryStore reservations, deletion cleanup and automatic polling deletion. An assembled supervisor with the production mutual-TLS adapter verifies exact empty/binary/65,507-byte native UDP delivery to an owned TLS node fixture; pause closes its stream, releases the budget and leaves the port reservation intact. Real Redis fault handling for this new supervisor, process-level service restart and real KVM delivery remain unverified; earlier allocation/listener Redis evidence does not establish these service behaviors.

Final isolated cluster library tests: 82 passed, one ignored. Control-plane integration tests: 28 passed. Optional Redis tests are not new live Redis evidence for this run. Sources and exact logs are hashed in manifest.json. Builds ran only in `/var/tmp/hm-egress-log-mA2CCL` with accepted core hashes and exact eight-module/export byte alignment. Protected root core files were not read or built.
