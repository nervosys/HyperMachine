# Streamed integrated CLI volume downloads

hm sandbox vm volume download ID DESTINATION --path PATH uses the volume bearer token without loading/forwarding HV2_API_KEY, requires HTTPS or loopback HTTP, and inherits timeout/custom-CA/redirect policy. It streams at most 4 GiB into a temporary file in the destination directory, flushes and syncs the completed file, then publishes with tempfile persist_noclobber. Existing destinations, including symlinks, are refused before network contact. Ordinary response/write failures leave no published destination and discard staging. A race creating the final name is handled by the no-clobber publication primitive; no overwrite fallback is used. The returned JSON contains local path and byte count.

All four shipped volume CLI tests pass, including exact 512 KiB binary download, an existing-destination refusal without a second server contact, and a truncated response that leaves no destination or temporary file. Upload and management tests still pass. Twelve existing VM CLI regressions pass. Actual CLI upload/download runs through the control router to real shared-volume daemons verify exact local/disk bytes and repeat-download refusal, alongside existing management, node termination, peer access, restart and cleanup checks. Before/after input identities and exact tested sources are archived.

This uses local HTTP, MemoryStore and dev/test binaries. New-command TLS/mTLS, full 4 GiB transfers, unknown-length overflow, destination-creation race injection, memory instrumentation and fleet/network-storage performance remain unverified. File contents are synced, but parent-directory power-loss durability is not claimed. Hard termination can leave a private local temporary file. No guest, production deployment or competitor win is established.
