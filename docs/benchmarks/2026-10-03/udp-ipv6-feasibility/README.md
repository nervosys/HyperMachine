# IPv6 UDP guest-kernel feasibility

The accepted kernel boots a real KVM guest with IPv6 loopback enabled: /proc/net/if_inet6 lists ::1 and /proc/sys/net/ipv6/conf/lo/disable_ipv6 is zero. The static owned fixture then creates two IPv6-only UDP sockets, binds both explicitly to ::1 on random ports, sends empty, binary and 65,507-byte datagrams, and verifies exact bytes, source family, loopback address and sender port. All three sizes pass within bounded receive/guest-command deadlines. No explicit fragmentation override is needed in this run; the probe records if EMSGSIZE requires enabling local fragmentation.

The fixture runs over the real authenticated control API HTTPS/node mTLS/Redis/KVM stack. The ordinary IPv4 tunnel checks continue to pass with the updated fixture image: CLI peer isolation, empty/binary/maximum payloads, trust/key refusal, malformed-frame recovery and pause/resume/delete. All ten combined checks pass; owned services are reaped and guest inventory is empty.

This verifies a prerequisite for an IPv6 feature, not IPv6 forwarding through the guest agent, node API, control plane or CLI. Those paths currently select IPv4 loopback and hv2-udp/1. Native public IPv6 UDP exposure is also incomplete. The probe sends datagrams wholly inside the guest; it is not a performance benchmark or a reply through the HyperMachine tunnel.

The current static echo fixture adds an explicit --ipv6-probe mode while preserving its default IPv4 echo behavior. The checker adds optional --probe-ipv6; existing benchmark defaults are unchanged. Reproduce by compiling udp-guest-echo.c with gcc -static -O2 -Wall -Wextra -Werror, building a fresh image with the archived image builder and exact recorded agent/base inputs, then running the checker with --tls --mtls --probe-ipv6 and recorded inputs. Exact image/probe/binary input hashes and reports are archived. The prior immutable echo image was not overwritten.

Implementing the feature requires explicit IPv6 destination-family selection in the agent operation, host forwarding, authenticated node/control routes, upgrade protocol negotiation and CLI. Verification must cover IPv4 compatibility, IPv6-only listener reachability, family mismatch refusal, byte bounds, peer isolation, TLS/authentication and lifecycle closure through the full stack. The demonstrated guest kernel supports proceeding with that work. Other kernels and native public networking remain unverified.
