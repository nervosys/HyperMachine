# Integrated volume management CLI

hm sandbox vm volume create/list/inspect/delete now use the existing API client, API-key environment configuration, timeout and custom-CA option. Names/IDs are validated against the daemon's 1–64 ASCII alphanumeric/underscore/hyphen contract. Management replies are bounded to 64 KiB; listings to 1 MiB. Creation and inspection return the volume bearer token in JSON, as the authenticated API does. Successful deletion has no output. API conflicts and authentication errors fail the command.

The shipped-binary protocol test passes all four operations, exact create body/path/method, platform authentication, empty deletion output, conflicts, wrong key and invalid-name refusal. Twelve existing sandbox VM CLI protocol tests pass. The actual CLI binary also executes create/list/inspect/delete through the real control-plane router to two real daemons sharing a local volume root; listing contains both expected volumes, inspection matches the created metadata and deletion removes the CLI-owned volume directory. The broader volume-routing tests, node termination/peer access and restart checks also pass. All processes/tasks are reaped or cancelled and awaited.

Exact input hashes were recorded before/after the real run. Current CLI/test source bytes match the isolated accepted-core checkout. The initial CLI compile used offline dependency resolution in the isolated checkout; final checks use --locked with the archived isolated Cargo.lock. The root lockfile is unchanged. No protected root core source was compiled. No operational tokens or payloads are archived; synthetic fixture credentials are in test source.

This closes management CLI access, not integrated streaming upload/download. The Python upload helper remains separate. Tests use local HTTP, MemoryStore and dev/test-profile binaries; Redis/TLS/mTLS/new-command transport, shipped control-plane executable, KVM mounts, network storage, fleet rollout and competitor performance are not established here.
