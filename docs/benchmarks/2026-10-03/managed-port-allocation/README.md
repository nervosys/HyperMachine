# Managed public-port allocation primitive

Memory and Redis stores now reserve stable public ports for sandbox machine ports, with TCP, UDP or both as reservation metadata. Updates retain the public port; concurrent requests share an atomic allocation, enforce a 16-port sandbox limit and a bounded allocation window, and refuse a different stored owner. Sandbox deletion removes its reservations. The trusted owner identifier is not an API credential; first-claim authorization remains the responsibility of the future management API.

Validation ran in the isolated Linux checkout `/var/tmp/hm-egress-log-mA2CCL`, using the accepted core sources, not the modified root core files. Default cluster library tests: 53 passed, one ignored. The ignored owned Redis test was separately invoked and passed: concurrent contract, AOF-backed process restart, wrong-type refusal and ACL-denied write/delete/cleanup preserving records. Control-plane integration tests: 28 passed. Existing optional Redis tests are not evidence of a live external Redis run. New Redis evidence uses only a temporary owned Unix-socket server and namespace, cleaned up by the test.

Redis writes preflight command permissions before modifying either index and require Redis 7 ACL scripting support. These checks establish datastore process-restart persistence, not physical power-loss durability. Public listeners, authenticated owner-specific management, gateway recovery, guest-reboot forwarding and native-wire performance remain unwired and unmeasured. No competitor performance claim follows from these tests.
