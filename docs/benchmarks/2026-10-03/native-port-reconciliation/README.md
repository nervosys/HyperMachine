# Native listener desired-state reconciliation

A bounded registry reconciles complete reservation snapshots with exclusive native TCP/UDP bindings. Identical bindings survive; removed or changed bindings close before asynchronous rebinding. Failed updates remain unbound and are retried. This fail-closed choice may interrupt traffic during protocol changes. Cancelling reconciliation cannot retain removed/changing listeners: they have already been dropped. Relay tasks are not implemented and would require their own lifecycle cancellation. No store reservation is modified by reconciliation.

Duplicate public ports, duplicate sandbox/machine destinations, invalid records and oversized snapshots close all registry listeners. Gateway capacity must be 1–4096 ports. Store read failures also close all listeners. Redis snapshot reads now check hash fields against each record's public port or machine port, refusing ambiguous field/record mappings rather than treating HVALS alone as authoritative.

Isolated validation: 58 cluster library tests passed, one ignored. The ignored owned Redis test was explicitly run and passed, and 28 control-plane integration tests passed. Optional legacy Redis tests are not evidence of a live external Redis run. New owned evidence covers AOF-backed Redis process restart followed by registry reconstruction on the same allocated port, competing native TCP/UDP bind refusals, corrupted global field and type refusal, per-VM field refusal, correction/rebinding and sandbox deletion followed by exact socket release. The server uses an owned temporary Unix socket, namespace and directory and is killed/reaped by the test. Loopback tests also cover exact TCP/UDP payloads and protocol-update bind failures.

The isolated checkout was `/var/tmp/hm-egress-log-mA2CCL` with accepted core hashes; protected root core files were not read or built. Current four source files match the isolated checkout byte-for-byte. Hashes and exact test logs are archived. This proves library-level listener recovery after datastore process restart, not a running gateway service restart, guest reboot, external network delivery, physical power-loss durability or performance superiority. Public relay, periodic gateway worker, bounded peer tasks and authenticated owner-specific management remain unwired.
