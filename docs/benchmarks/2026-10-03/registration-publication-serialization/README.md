# Initial publication and reconciliation serialization

Four fresh real KVM profiles pass 28 checks each. The controlled phase holds writes on an owned Redis instance for at most 1000 ms, starts initial creation, observes its locally running guest while the request remains pending, starts concurrent reconciliation, and observes both requests remain pending for 50 ms. Explicit UNPAUSE releases writes. Original creation succeeds with the same ID; reconciliation then returns 409 with no uncertain local registration, and discovery is empty. The guest is deleted. Existing initial/resume SET/XADD refusal, CLI discovery/recovery, authorization, exact forwarding and cleanup checks also pass. All guests/processes are cleaned up.

Source inspection confirms create acquires the same per-sandbox transition lock as reconciliation before calling register. Therefore the additional atomic publisher guard from ../registration-publisher-ownership was redundant and has been removed from production and isolated source. That immutable archive records a withdrawn candidate, not current production behavior. Its prior race diagnosis was incorrect. Failed earlier race fixtures expected an immediate in-progress 409; actual reconciliation waits for the lock. Accepted serialization evidence is in these fresh runs, not the failed attempts.

The write hold is explicitly released in finally. The bounded hold and overlapping pending futures demonstrate the observed schedule, not every distributed interleaving or cancellation behavior. No duplicate live guest was observed; exactly-once event delivery is not established. Automatic reconciliation, startup cancellation and machine-crash recovery remain incomplete.

Current source matches the previously verified 133-file baseline catalog. The immutable node binary is the accepted pre-guard discovery daemon; control/CLI/gateway/kernel/image are unchanged matched inputs. No rebuild was needed after removing the redundant source because the existing immutable node exactly corresponds to that baseline. Reports/logs, source/checker/driver snapshots, source context and manifest retain provenance. Credentials and private keys are excluded.
