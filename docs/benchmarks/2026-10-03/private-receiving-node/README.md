# Receiving-node private TCP implementation

Final isolated daemon tests: **61 passed, 0 failed, 2 existing KVM tests ignored**. Cluster tests with owned Redis: **99 passed, 0 failed, 1 existing ignored**. Optional Redis ACL fixtures are not enabled. The final development daemon builds successfully; its frozen path and SHA-256 are in daemon-inputs.json.

The receiving route is `GET /sandboxes/{sandboxID}/private-ports/{port}/tcp`, using the existing bodyless HTTP/1.1 `hv2-tcp/1` upgrade. It requires an active cluster, a nonempty bounded cluster token and all mutual-TLS inputs. Cluster middleware checks the token; the route additionally refuses duplicate token fields. Internal route/source-node headers are single, bounded and path-bound; route IDs and generations are validated before store lookup.

Implementation loads fresh atomic source/destination membership and records, requires registered live source/destination nodes, verifies node placement and same-owner/shared-tag generations, and checks actual destination local registration and VM identity. Same-node sources also require a matching locally running, committed VM. Cross-node source labels rely on the existing mutually authenticated, shared-credential cluster trust; this is not certificate-bound per-node or per-VM identity. Trusted source gateway code must derive its context and check its own local registration before sending.

The destination lifecycle lock covers guest port opening and stream registration. Authorization is repeated after opening before accepting the upgrade. Temporary stream ownership closes setup on cancellation/refusal; a private relay cancellation guard closes the stream if its task is dropped. Destination activity and same-node source activity remain busy during the relay. A 128-connection node budget bounds private relays. A one-second authorization monitor closes on revocation/state lookup refusal or error, with a three-second lookup timeout; a ten-minute timer bounds lifetime, subject to an in-progress lookup. These runtime behaviors are implemented but not yet verified through a real guest private tunnel.

Three new daemon unit tests verify transport prerequisites, bounded strict/path-bound context and reusable connection admission. One new cluster test verifies bounded wire identities and canonical generations. Existing daemon and cluster suites pass, including owned Redis membership/route contracts. No private KVM payload, half-close, revocation, migration, cancellation or overload claim follows from unit tests and compilation.

The first compile failed because the daemon referenced a crate-private port validator; validation was moved into the public route-claim model before final verification. That failed log is excluded from runtime evidence. The intermediate v1 daemon lacked the relay-task cancellation guard and is not the accepted final binary. All evidence here uses the final v2 daemon.

Builds run only in `/var/tmp/hm-egress-log-mA2CCL`; all 134 permitted root/isolate source hashes and separately accepted isolated core hashes match. Protected root core files were neither read nor built. Source guest gateway dialing, private DNS, address allocation and create/fork integration remain unfinished. No private-network or competitor performance advantage is established.
