# Real-route CLI volume browsing

The shipped CLI `volume ls` and `volume stat` were run through the actual control-plane router to two real sandbox daemon processes sharing an owned temporary volume directory. Controlled node-store eligibility selects each daemon in turn. Both commands return cli.bin as a file at /cli.bin with the exact 512 KiB size; the listing contains exactly that entry. They succeed with an invalid platform API key, confirming content bearer authentication. A wrong volume token produces 401 through each node.

Both volume_routing integration tests pass, including existing management, binary upload/download and refusal checks, route membership changes, selected-node termination during an incomplete atomic upload, peer access, restart preservation, and owned cleanup. The four input binary/image hashes are unchanged before/after; tested router/store/key/CLI/test source hashes match the root worktree and accepted isolated checkout.

Reproduce in the accepted checkout with HM_VOLUME_TEST_DAEMON, HM_VOLUME_TEST_CLI, HM_VOLUME_TEST_KERNEL and HM_VOLUME_TEST_INITRD set to their respective paths, then `cargo test --offline --locked -p hv2-cluster --test volume_routing -- --include-ignored`. This uses the real router in the test process with MemoryStore and loopback HTTP. It does not exercise a separately launched control-plane service, Redis, TLS/mTLS, a guest mount, large listings, network storage, automatic membership failover, or a competitor. It supersedes the earlier browsing archive's pending real-route check within this stated scope.
