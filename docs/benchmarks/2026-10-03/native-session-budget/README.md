# Shared native TCP/UDP admission budget

A cloneable session budget now provides one admission pool for multiple native TCP and UDP listeners. Each admitted TCP connection or UDP peer owns a permit throughout upstream opening and relay lifetime; dropping its task returns the permit on completion, error, panic or cancellation. New sessions are refused/dropped when the pool is exhausted, while existing UDP peers continue using their already admitted session. Per-listener limits and fixed eight-frame UDP queues still apply. Configuration accepts 1–65,536 aggregate sessions; this is a session count, not a byte/RSS or fleet-wide quota.

New `serve_tcp_with_budget` and `serve_udp_with_budget` APIs accept a shared pool. Existing convenience APIs construct separate pools bounded by their existing per-listener limits. A future gateway worker must pass the same budget to all its listeners to establish actual gateway-wide enforcement; no running gateway is wired by this change.

An owned fixture binds native TCP and UDP simultaneously to the same public port and shares a one-session pool. Live TCP blocks UDP peer setup without opening a second tunnel. TCP shutdown returns the slot; UDP then opens and blocks new TCP setup on another listener. Final shutdown restores the pool and exact socket rebinding succeeds. Existing error/timeout/panic and same-peer recovery tests continue to pass through budgeted admission, including single-session fixtures. Panic recovery applies to unwinding tests, not panic=abort processes. Owned echo/relay tasks are aborted or awaited.
