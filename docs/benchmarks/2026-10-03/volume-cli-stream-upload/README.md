# Streamed integrated CLI volume uploads

hm sandbox vm volume upload ID SOURCE --path PATH streams a Tokio file through reqwest rather than collecting its bytes. Regular files up to 4 GiB are accepted. Atomic replacement is default; --in-place, --no-clobber and --force map to server query fields. Uploads use HV2_VOLUME_TOKEN with a sensitive bearer header, require HTTPS or loopback HTTP and never load/forward the platform API key. The existing custom-CA and request-timeout options apply; redirects remain disabled. Responses are bounded to 64 KiB and returned size must match source metadata. Source must stay stable during upload.

Both shipped CLI volume tests pass, including a 512 KiB binary stream, encoded path, atomic/force flags, conflict refusal, and success with an intentionally invalid platform API-key header value that must not be used. Twelve existing VM CLI protocol regressions pass. The actual CLI also streams 512 KiB through the real control-plane router to a real shared-volume daemon; exact disk bytes are checked, and a repeated create-only upload fails without changing them. Management, other volume routing, node-kill/peer-access and restart checks also pass. Input identities were verified before/after. Test source files/listeners and child processes are cleaned up.

Tests use local HTTP, MemoryStore, dev/test binaries and a local filesystem. New-command TLS/CA behavior, full 4 GiB transfer, source mutation, streaming memory instrumentation, Redis, network storage, fleet performance and competitor measurements remain unverified. This adds integrated upload, not download. Atomic post-publication error and hard-kill staging limits remain as documented. Root protected core sources were not compiled; isolated accepted sources were used.
