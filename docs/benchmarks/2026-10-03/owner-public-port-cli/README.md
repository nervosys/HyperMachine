# Shipped CLI public-port management

The shipped CLI now provides `hm sandbox vm public-ports expose ID --port N [--protocol tcp|udp|both]`, `public-ports list ID` and `public-ports remove ID --port N`. Protocol defaults to TCP. Ports must be 1–65,535, and unsupported protocol/owner override flags are refused before requests. The commands use the existing verified API TLS client, environment API key, no redirects and bounded 16 KiB JSON responses. Server error bodies are omitted from refusal messages so a server cannot reflect an API credential through an error. Exposure/listing print reservation JSON; successful removal prints nothing, matching established delete-command behavior. Owner identity comes from server-side policy/VM records, not CLI input.

All 148 CLI library tests pass. New parser cases cover default TCP, all protocol values, missing owner override support and invalid ports/protocols. An owned HTTP listener checks method/path/body/credential forwarding, refusal-body redaction and oversized-response rejection. The whole suite also covers existing UDP, TCP, MCP, files and lifecycle helpers. The CLI built successfully with offline locked Cargo in the accepted isolated checkout and was frozen to a fresh path. A test-only response-bound assertion was added after the first build; the final rebuild has the same executable hash because production code did not change. Earlier binaries and checker attempts are not promoted as different performance candidates.

Two final Redis/mTLS/KVM profiles pass twenty-two checks each: IPv4/two UDP peers and IPv6/eight. The managed VM is actually created by the shipped CLI's V2 create command, and its trusted configured creator is checked in Redis before exposure. Independent API creation with forged public owner context is also checked and then removed. CLI expose/list/remove are used for the native reservation and protocol changes. Wrong, observer, inventory-only, unassigned and legacy-admin credentials are refused; an explicitly ownerless legacy VM is also refused. Actual policy SIGHUP rotation revokes the old CLI key while preserving creator and allocation for the replacement. Removal has successful empty stdout, removes the reservation and closes the live native TCP session/listener. TCP default is verified against the actual guest, then updating to both closes the previous session and restores native TCP/UDP. The same port is retained for protocol changes and reused within the owned one-port pool after removal.

The profiles retain exact native 1 MiB TCP and empty/binary/65,507-byte UDP correctness, source peer separation, fork owner/port exclusion, guest pause/resume and actual deletion cleanup. All owned processes are reaped, zero guests remain, and generated API/cluster credentials plus the CLI-created VM's workload token are absent from logs. Creation stdout containing a legitimate per-VM access token is parsed privately and not archived. Default guest UDP remains IPv4; IPv6 is the public/CLI ingress family. These are functional/lifecycle profiles, not new performance measurements.

The node/control/gateway/kernel/dual-service image are reused from the preceding accepted owner API context. Only CLI production code changes here. Current root/isolate bytes match for 133 permitted sources/manifests/tests, with accepted isolated core hashes revalidated. Protected modified root core sources were not read, built or staged. This is limited accepted-context verification, not whole-root validation. Reports verify binaries, guest/kernel and exact checker hashes before/after. The initial checker wrongly expected JSON for a successful empty deletion response; two failed attempts are excluded, and the final parser handles empty stdout. Earlier successful profiles without CLI creation are also excluded from this final archive. All exact source snapshots, reports, logs and provenance are covered by manifest.json. No certificate private keys or policy files are archived.

Reproduce with compatible owner-aware host binaries, this CLI, a dual-service guest image and a fresh output directory:

```sh
python3 tools/check-udp-cluster-kvm.py --daemon /path/hv2-sandboxd \
  --control-plane /path/hv2-control-plane --cli /path/hm \
  --kernel /path/bzImage --initrd /path/native-fixture.cpio.gz \
  --native-gateway /path/hv2-native-gateway --tls --mtls --owner-context \
  --owner-port-api --owner-port-cli --output /fresh/results
```

Add `--local-ipv6 --peer-count 8` for the second profile. Management still requires operator-configured principal IDs, allocation window, gateway and network routing. API acknowledgements do not form listener readiness/revocation barriers. Sixteen simultaneous public listeners, explicit legacy adoption/ownership transfer, guest reboot, public Internet/DNS operation, central organization identity, sustained resource measurements and competitor performance remain incomplete or unverified. This CLI verification does not establish superiority across all features or metrics.
