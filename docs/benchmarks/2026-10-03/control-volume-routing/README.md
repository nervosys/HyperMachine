# Existing sandbox control-plane volume routes

A focused real-HTTP integration test passes against the existing hv2-cluster control plane and two owned protocol nodes. It verifies management authentication before node contact; create and ID inspection select the same node as content PUT/GET; exact atomic/force/encoded-path query preservation; 256 KiB binary content roundtrip; volume bearer authentication without a platform API key; platform API keys not forwarded to nodes; the control plane supplies its configured cluster credential instead of accepting the client's supplied one; wrong bearer refusal preserves bytes; duplicate volume listings across nodes merge once. Three owned server tasks are cancelled and awaited after checks.

The tested control/keys/store source bytes match the root worktree; compilation uses the isolated accepted-core checkout. This is protocol routing evidence, not a real volume-filesystem or KVM test. Existing daemon storage checks remain separate. Node membership changes and shared-root failover, Redis-backed fleet routing, TLS/mTLS forwarding and storage guarantees are not covered here.

This corrects the earlier mistaken node-only finding: that search inspected hv2-api, the general VM API server, rather than hv2-cluster, the sandbox control plane. Existing routes already support management and streaming content. Current guides and the comparison matrix are corrected; immutable earlier archives retain historical statements and are superseded by this evidence. No new production route was added and no performance/competitor claim follows.
