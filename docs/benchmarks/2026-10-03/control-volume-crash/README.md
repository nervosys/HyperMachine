# Selected volume node termination during atomic upload

Both volume-routing tests pass, with the real-daemon test extended to an unfinished atomic upload. The fixture first publishes a verified 1 MiB binary file through the control plane, limits routing eligibility to node zero, begins a replacement, and waits until an owned .hm-upload-* file contains request bytes. It then kills/reaps that real daemon. The control plane returns HTTP 502 rather than success. The staging file remains with mode 0600 because a hard kill cannot run Drop cleanup. Eligibility changes to the live peer; exact previous destination bytes remain readable through the control plane. Both daemon processes are restarted, content remains exact, bearer refusal and merged listing pass, and explicit owned-volume deletion removes destination and orphan staging data. All children and the control-plane task are reaped/cancelled and awaited.

This uses the actual current control router with MemoryStore in the Rust test process and two real hv2-sandboxd processes sharing a local filesystem. Input identities are verified before/after. Source and logs are frozen here. No automatic production orphan deletion or automatic retry was added. The test records the recovery boundary: old bytes survive a pre-publication process termination, but orphan staging files require operator review. The explicit DELETE is scoped to the temporary owned test volume.

This is a process kill after partial staging, not power loss, post-rename termination, storage failure, Redis heartbeat expiry, TLS/mTLS or network-filesystem behavior. Node removal is controlled test setup, not an automated health failover claim. The client closes its unfinished write side after node termination and the response is bounded by five seconds. No guest, throughput or managed competitor measurement occurs.
