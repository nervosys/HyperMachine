# Streaming atomic volume upload client

The new tools/upload-volume-file.py helper streams a regular file in 128 KiB chunks, up to the server's 4 GiB limit, and uses atomic replacement by default. It accepts a direct node HTTPS endpoint with system/custom CA validation, or loopback HTTP, and obtains the volume bearer token only from HV2_VOLUME_TOKEN. It sends no platform API key, follows no redirects, bounds the response to 64 KiB, and checks returned size. --in-place preserves the server's compatibility mode; --force creates parent directories.

The owned two-node fixture invokes the helper with a 1,048,586-byte binary file, verifies exact readback on both daemons, and passes all creation/token/atomic-abort/root-upload/restart/cleanup checks. Every owned process was reaped. Source, report and daemon/kernel/initrd identities are frozen here. This is a Python operator helper, not an hm sandbox vm subcommand or E2B SDK extension. The control plane currently has no volume management/content routes; operators must use a reachable node sharing the intended volume root. HTTPS/custom-CA behavior, a full 4 GiB upload, source mutation during upload and timeout faults were not exercised by this loopback check. Keep the source stable during upload. Failures after publication may leave the replacement visible.
