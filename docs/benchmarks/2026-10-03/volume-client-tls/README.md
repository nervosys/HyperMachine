# Volume upload client HTTPS and refusal checks

All seven owned fixture tests pass. Coverage: a 1 MiB binary upload through a generated localhost certificate trusted via --ca-cert; exact bearer authentication and payload digest; query encoding for a path containing spaces and ampersands; atomic/force flags; absence of the environment's platform API key on the wire; rejection of untrusted certificates and trusted-but-wrong hostnames before HTTP payload arrival; 307 refusal without a second request; missing token, non-loopback plain HTTP, and a sparse 4 GiB+1 source refused without a request; empty in-place upload; delayed-response timeout; and wrong response size refusal. Client subprocesses have five-second test bounds. Fixture listeners, request threads and generated certificate/key directories are closed and removed.

These are owned local HTTP/TLS protocol fixtures, complementing the real two-daemon binary roundtrip in ../volume-upload-client. They do not establish public CA operation, proxy compatibility, source-mutation handling, maximum-size successful uploads, slow-drip total-deadline behavior, memory instrumentation, storage durability or competitor performance. The test sparse file tests rejection, not a 4 GiB transfer. Raw tokens, generated keys/certificates and uploaded bytes are not archived. Source and complete test log are frozen with hashes.
