# Connected volume upload deadline

The helper now computes a deadline before connection setup and, after connecting, starts a watchdog for the remaining time. At expiry it shuts down the connected socket, interrupting upload sends, response headers and response-body reads even when bytes keep arriving. Completion after the deadline is refused. The watchdog is cancelled/joined and the connection closed on every exit. This prevents successful connected transfers from extending the requested timeout through a slowly arriving body.

All eight owned client tests pass. The new fixture sends a response byte every 60 ms while the client requests a 150 ms timeout; the subprocess fails in less than the 800 ms test allowance. Existing trusted HTTPS, hostname/CA refusal, redirect, token/size checks, empty upload and delayed-response tests pass. The current helper also passes the real two-daemon atomic binary upload/check/restart/cleanup fixture. No raw tokens, private keys or uploaded bytes are archived.

This is a connected-network deadline, not a guarantee that the process exits by the requested time under every platform condition. System DNS resolution and local file operations can outlast socket timeouts. TLS connection setup uses the existing bounded socket timeout, and elapsed setup time is deducted before transfers proceed. A timeout can occur after server publication; inspect the destination before retrying. Test timing includes subprocess startup and deliberately allows scheduling overhead. There is no network-storage, public CA, fleet or competitor performance claim.
