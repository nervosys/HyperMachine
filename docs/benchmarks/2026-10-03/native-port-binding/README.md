# Exclusive native port binding

The native binding primitive opens TCP, UDP or both on one durable reservation's public port and the operator-selected interface. No reuse options are enabled. A failed dual-protocol bind releases its partially opened TCP socket; protocol updates bind the new socket before releasing the old one and retain the previous allocation and listeners if binding fails. Identity changes (sandbox, machine port, public port or owner) are refused. Dropping the binding releases its listeners. This primitive does not delete a reservation or claim that a failed store-to-listener update was rolled back.

Tests use actual owned loopback sockets on ephemeral IPv4 and IPv6 ports, verify binary TCP and exact empty/binary/65,507-byte UDP datagrams, competing bind refusal, occupied-socket protocol-update failures, successful transitions and release/rebind. The loopback datagram checks do not exercise guest forwarding, fragmentation on external networks or Internet ingress. Default cluster library tests: 56 passed, one ignored; control-plane integration tests: 28 passed. Existing optional Redis tests are not external Redis evidence; the prior owned Redis allocation test is archived separately. Source and logs are hashed in manifest.json.

Builds used isolated `/var/tmp/hm-egress-log-mA2CCL` with the accepted core source hashes. Root protected core sources were neither read nor built. Exact new module/export bytes matched the isolated checkout. This is an unwired library primitive: no control-plane route, public traffic relay, gateway reconciliation, peer-resource manager, authenticated owner API or guest-reboot verification exists yet. Existing API keys remain team-scoped and sandbox records have no owner identity; credential fingerprints alone cannot establish first-claim VM ownership. Native public service parity and performance remain unverified.
