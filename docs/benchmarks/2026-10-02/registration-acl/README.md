# Registration write-permission preflight

The baseline regression failed: denying `SADD` to a temporary Redis user left the sandbox record written before named registration failed. Redis Lua errors do not roll back prior writes. Index-type checks alone did not prevent this permission failure.

Named registration now checks the exact four write commands and their key arguments with `redis.acl_check_cmd` before its first write. Denied `SET`, `SADD` and `HSET` each leave the VM absent, the reservation pending and both registration indexes unchanged. Ownership checks, index-type checks and exact replay behavior remain in place. This prevents the tested ACL partial-write failures; it does not promise recovery from every server failure or complete pending-operation reconciliation.

The API requires Redis 7 or a compatible server exposing this Lua capability. A server without it returns an error before new named registration writes. Existing exact replay can succeed without writes. Other legacy store operations are unchanged and are not covered by this permission guarantee. The capability and its version are documented in the [Redis Lua API reference](https://redis.io/docs/latest/develop/programmability/lua-api/).

The corrected full library run passed 38 tests against an owned loopback Redis server, including the shared contract, index-type faults and the new ACL regression. Both runs removed their temporary ACL user and stopped Redis with exit code 0. Windows library tests passed 38 tests with Redis-specific tests skipped; strict library/test Clippy passed on Windows and Linux. Linux used an isolated source copy with the committed boot inputs from [node-completion](../node-completion/README.md); provisional boot edits were excluded. No VM or performance comparison was run here.

`before.tests.log` preserves the failing regression; `after.tests.log` preserves the passing full suite. Complete before/after store files, the patch against `80364f7`, runner, Redis logs and reports are hashed in `manifest.json`. To reproduce on an owned Linux test host, apply the patch and run `python tools/check-registration-acl.py --source PATH --output REPORT.json`. The dedicated `HV2_TEST_REDIS_ACL` variable opts into temporary ACL-user creation; it should identify an owned test server. Run `python docs/benchmarks/2026-10-02/registration-acl/verify.py` to verify the archived evidence.
