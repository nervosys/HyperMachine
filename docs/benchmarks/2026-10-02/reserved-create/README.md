# Named creation with real KVM, Redis and authenticated SSH

All 20 functional checks passed using the control-plane creation implementation from `a393113`, a live owned Redis server and the previously accepted KVM daemon. Creation bound the requested name; both v1 and v2 create routes refused duplicate requests with 409; an inventory-scoped key could not create. The shipped CLI inspected reserved ownership and OpenSSH reached the guest by name over API TLS and node mTLS. Exact 1 MiB binary transfer, exit code 7, incorrect client-key rejection and incorrect host-key rejection passed. Deletion released ownership, and another VM successfully reused the same creation name.

This run does **not** resolve inherited fork metadata. The accepted older daemon copied the parent's `hm.name` into the child. Reserved lookup refused that legacy conflict with 409, named SSH failed, and removing the child restored parent lookup. This is evidence of the remaining fork/migration gap, not uninterrupted parent ownership after a fork. Existing-VM aliases without metadata have separate [20-check evidence](../reserved-alias/README.md).

Cleanup left zero sandboxes, with no cleanup errors, and stopped all 22 registered processes. The environment was local WSL nested KVM, with 1 vCPU / 1024 MiB guests. This is functional evidence with no latency, throughput or competitor performance claim. Multiple control-plane creation races and uncertain node outcomes are covered by the 21 HTTP tests on Windows and Linux; this KVM run used one control plane and sequential duplicate requests.
